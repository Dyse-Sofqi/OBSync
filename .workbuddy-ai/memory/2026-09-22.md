## 新增功能：图片同步（Cloudflare R2）—— 双副本镜像 + 双向删除 + 笔记内裁剪压缩

用户需求原文：「在"仓库同步"后添加"图片同步"标签页，增加将仓库图片同步到 R2 的能力，
实现双副本架构，指定图片文件夹，本地和云端各存一份，双向删除同步，支持在笔记内直接对图片进行裁剪和压缩。」

### 三条设计决定（下次改这块之前先读）

1. **双向删除靠状态清单**。只看两边现状无法区分「用户删了」与「另一边新增」——
   同一个「本地有、云端没有」两种解释都成立。所以记「上次同步时两边一致的快照」。
   **不变量：只有清单里记过的路径才允许产生删除动作。**
   清单丢失（换设备、清存储）最坏只会让两边补齐，**不会**把任何一边清空。
   实现在 `decide()` 里那两个 `if (tracked)` 分支，`planSync.test.ts` 有专门用例钉着。
2. **不用 `crypto.subtle`**：移动端可能不是安全上下文，且会污染整条签名链成 async。
   自己写 SHA-256，用 FIPS 180-4 / RFC 4231 / **AWS 官方向量**校准。
3. **状态清单放 localStorage 而非 vault 文件**：它是「这台设备的观察结果」，
   随 git 同步会被别的设备覆盖。按 **vault 路径**而非对象键存 —— 用户改前缀不会让清单失效。

### 配置语义（容易混，已写进注释与测试）

- `folders` = **管哪些**（唯一的删除边界）；`prefix` = **放在桶的哪儿**。
  两者各管一件事，都成立才归本插件处理。配 `prefix: "images/"` + `folders: ["images"]`
  时对象键是 `images/images/a.png` —— 不是 bug，但值得知道。
- `settings.images.prefix` 存**用户原文**，归一只发生在 `buildR2Config` 里。

### 本轮补测试时发现并修掉的 7 个真问题

| 问题 | 症状 | 修法 |
| --- | --- | --- |
| `extensionOf` 取整条路径最后一个点 | `v1.0/README` → `0/readme` | 只看 basename；`index <= 0`（点开头文件名无扩展名） |
| `normalizeFolder` 先判「整个库」再剥斜杠 | `./` 归一成 `.` → **一个文件都匹配不上且无提示** | 先拆段再判断，丢掉空段与 `.` 段 |
| `parseListResponse` 截断但无 token 时报 `truncated:false` | 列举不完整被当成完整 → **删掉本地文件** | `truncated` 与 `next` 分开返回，以 `IsTruncated` 为准 |
| `plan.entries[].action` 冲突时写成 `upload`/`download` | 设置页那段 `=== "conflict"` 的警示配色是**死代码**，冲突画成绿色 | 冲突时写 `conflict`（执行仍按 `kind`） |
| `canonicalHeaders` 用小写名查原始键 | 传 `Host` 会取到 `undefined` 并抛 TypeError | 先归一成小写名的表再取值 |
| `normalizeEndpoint` 只认「含 `.`」 | `http://localhost:9000` → `localhost:9000.r2.cloudflarestorage.com` | 带 scheme / 端口也当地址 |
| `imageLinkCandidates` 把原始 `app://` src 也当候选 | 必然落空的一次查找；`linkHref` 是 `app://` 时没被还原 | 每个线索都过 `appUrlToPath`；带 scheme 的一律丢掉 |

另外：**自查脚本 `checks.mjs` 的「未使用的 i18n 键」把多行参数表的形参名当成了键**
（`counts` 的 `conflicts` 被报成死键）。以前没暴露只是碰巧 —— `upload` / `skipped`
这些形参名在代码里别处也有 `.upload` / `.skipped` 的访问，被当成「已引用」了。
加了 `paramDepth` 守卫（值以 `(` 开头时进入参数表模式，括号闭合才出来）+ 字符串感知的
`parenBalance`。

### ⚠️ 环境：pnpm 的 pre-run 依赖检查

`pnpm <script>` 现在会先做依赖状态检查，判定不一致就想**清空 node_modules 重装**，
非 TTY 下直接中止（`ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`）。
**没有让它清** —— 那是破坏性且慢的动作。改用等价命令直跑：
`node scripts/checks.mjs` / `npx eslint` / `npx tsc` / `node esbuild.config.mjs production` /
`node scripts/verify-mobile-load.mjs`。根因未查（全局 pnpm 11.21.0，`pnpm-workspace.yaml`
用了 11+ 的 `allowBuilds` 字段）。
