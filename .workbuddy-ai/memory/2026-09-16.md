### 实测发现（读文档看不出来，都是打真实接口才发现的）
1. **Gitee releases 默认升序**。不传 `direction` 时 `mindspore/mindspore` 首个返回 `v0.1.0-alpha`(2020)，传 `direction=desc` 才是 `v2.7.2`(2026)。直接照搬 BRAT 的 GitHub 逻辑会静默安装六年前的版本。
2. **Gitee 的 API raw 端点对匿名请求返回 401**（"登录失效，无权限访问该资源"），**即使公开仓库也如此**。匿名读文件必须走网页通道 `https://gitee.com/{o}/{r}/raw/{ref}/{path}`（302 → raw.giteeusercontent.com）。代价是必须显式给出 ref。
3. **Gitee 的 `html_url` 带 `.git` 后缀**，GitHub 不带。
4. Gitee 鉴权走 `access_token` **查询参数**，GitHub 走 `Authorization` 请求头 —— 这个差异无法用统一装饰器消除。
5. Obsidian `requestUrl` 的 `throw` 选项**默认 true**（400+ 直接抛异常），要自己处理状态码必须显式传 `throw: false`。
6. Gitee 的 `/v5/search/repositories` 匿名调用返回空数组，搜索功能在 Gitee 侧不可用。

### 验证
- `pnpm test`：78 项单测通过。
- `pnpm test:live`：11 项真实 API 测试通过（含一条对照实验，实证 Gitee 默认升序）。
- `pnpm build`：产物 35KB，仅 `obsidian` 一个外部依赖，无 node 内置模块被打包。

### 顺带发现
测试库里已装的第三方插件 `gitee-sync-plus` **不是真 git 实现** —— 只调 `api/v5` + `access_token` 做文件级收发，没有提交历史、分支、冲突处理。所以走真 git 是差异化，不是重复劳动。

## 接力会话一（同日）：阶段三完成

### 产出（同步模块 src/features/sync/）
- `gitManager` 抽象接口 + `simpleGitManager` 实现（状态映射、错误收口、
  pull 三态：merge / rebase / **reset = stash 保护 + hard reset**）。
  刻意不用 obsidian-git 的 update-ref + 普通 reset —— 那会让工作区与 HEAD
  脱节，下次提交把远端改动倒推回去。
- `auth.ts`：http.extraheader 经 simple-git 的 `config`（字符串数组）注入每条命令，
  不落盘；实例按「远端 URL + gitPath」缓存。
- `syncService`：promise 串行队列；sync = 提交→拉取→（再提交）→推送；
  **拉取冲突时链路立即停止**（SyncOutcome 新增 kind:"conflict"），
  在库根目录写《OBSync 冲突指南.md》。
- `automatics`：剩余时间模型定时器（时间戳存 localStorage，重启续表）。
- 状态栏（service 显式驱动）、源码控制视图、编辑远端弹窗、
  8 个命令、设置页（策略三态下拉 + gitPath）。
- esbuild 产物 190KB：simple-git + node 内置（child_process/fs/os/path）
  全部走 external，Electron 运行时可用 —— 与 obsidian-git 同构。

### simple-git 实测坑（详见 HANDOVER.md 第六节）
1. `config` 是字符串数组不是对象；`simpleGit()` 收 Partial<SimpleGitOptions>。
2. `git.log({max})` 错，要 `maxCount`（--max-count）。
3. 空仓库 commit 不抛错，返回 changes=0 摘要。
4. HEAD 未出生时 restore --staged 报错，用 `git rm --cached` 回退。
5. 无提交的仓库 `git branch` 输出为空。
6. push 不更新裸仓库 HEAD，测试环境要手动 symbolic-ref。
7. 测试机全局 autocrlf=true，内容断言要归一 \r\n。

### 测试
- simpleGitManager：**真实临时 git 仓库**驱动（mkdtemp + 系统 git），
  15 项覆盖 init/状态/提交/分支/推送/拉取/冲突/abortMerge/push 拒绝。
  提交身份用 addConfig 设仓库本地，不碰全局配置。
- syncService：可编程假 GitManager 验证编排（顺序/冲突停止/串行化，
  用带延迟的 status 计数直接观察 maxInFlight=1）。
- 全套 174 项单测绿（~30s，含真实 git 用例）；build 部署成功。
