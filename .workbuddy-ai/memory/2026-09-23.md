# 2026-09-23

## 改设计：去掉双向删除，改成「删本地图片时问一句」

用户原话：「双向删除容易引发歧义，所以不做了，用删除本地图片时，询问是否同步删除云端备份代替。」

### 为什么这个改动是对的（记下来，免得以后又想加回去）

双向删除的判断**本质上做不准**：同一个「本地有、云端没有」既可能是「用户删了
云端那份」也可能是「本地新增」，只能靠状态清单区分。而清单丢失（换设备、清了
存储）、或用户在两台设备上各删一边时，判断就会错 —— 错的代价是**删掉一份用户
没打算删的东西**。用户说的「歧义」就是这个。

改成问一句之后，判断的责任回到用户身上：他知道自己刚才删了什么、打算删到什么
程度。插件只负责把「云端也有这一份」这个事实摆出来。

### 新的形态

| | 之前 | 现在 |
| --- | --- | --- |
| `run()` | 上传 / 下载 / **删本地** / **删云端** | **只上传与下载** |
| 删除入口 | 计划里的 `delete-*` 动作，受两个开关控制 | `vault.on("delete")` → 攒批 → 弹窗问用户 |
| 云端没了 | 删本地 | 重新上传（镜像补齐） |
| 本地没了 | 删云端 | 下载回来；**除非**有墓碑 |
| 设置项 | `deleteLocalWhenRemoteDeleted` / `deleteRemoteWhenLocalDeleted` | `askDeleteRemote`（默认 true） |
| `SETTINGS_VERSION` | 4 | 5 |

### 墓碑（`SyncedEntry.remoteOnly`）—— 这次改动里唯一不显然的地方

用户删掉本地一张图、在询问里选了「保留云端副本」之后：本地没有、云端还有。
而镜像逻辑看到这个状态**只会想到「补齐」**—— 于是下一轮同步把那张图下载回来，
看起来像「删除没生效」。

所以 `keepRemoteBackup()` 记一条墓碑，`decide()` 在「只有云端」那一支里先看它。
墓碑不需要时间戳：云端那份消失时（别人删了 / 用户后来确认删除），`pruneState`
会因为两边都不存在而把整条记录剪掉。

**没点按钮直接关窗（Esc / 点外面）也按「保留」处理**，而且必须记墓碑 ——
「不表态」不能等于「什么都不做」。

### 迁移（v4 → v5）不是机械改名

两个老开关里只有一个有对应物：
- `deleteRemoteWhenLocalDeleted`（本地删了 → 云端也删）问的正是「删本地时要不要
  动云端」，与新字段同一个问题 → **接过来**。关掉过它的用户明确表达过「别动云端」，
  那就别拿询问去打扰他。
- `deleteLocalWhenRemoteDeleted`（云端删了 → 本地也删）**没有**对应物，那个方向
  的行为被整个去掉了 → 静默丢弃。把它翻译成 `askDeleteRemote` 会让「云端的变化
  影响本地」以另一种形式复活（方向正好相反）。

因为 `mergeWithDefaults` 只保留默认值里存在的键，老字段在 `merged.images` 上已经
看不到 —— 迁移得从**原始数据**里读，所以 `normalizeSettings` 里多了一个
`readRawImages(loaded)`。

### `noteDeleted` 身上的一串守卫（每一个都对应一类「不该弹的窗」）

`instanceof TFile`（删文件夹也触发事件，而 `images.png` 这种文件夹名会被
`isImagePath` 认成图片）/ `isImagePath` / `isInsideFolders` / `enabled` /
`askDeleteRemote` / `isConfigured` / **`hasRemoteBackup`**（挡掉绝大多数删除：
用户删的多半是从没同步过的截图）。

攒批 400ms：一次选中十张图删掉会发十个事件，逐个弹窗是灾难。

### 这次踩到的两个坑

1. **测试里 `seed` 出文件来当事件参数，却忘了把它从库里删掉。**
   Obsidian 的 `vault.on("delete")` 是在文件**已经消失之后**才触发的 ——
   于是被测代码看到的还是「文件还在」，整条路径走不到。
   给 `fakeImageVault` 加了 `remove()`，把这个时序如实还原。
2. **stub 的 `TFile` 缺 `vault` 字段**（真实 `TAbstractFile` 有），
   而 `noteDeleted(file: TAbstractFile)` 用的是真实类型 → 编译不过。
   选择在测试里断言一次，而不是给替身加一个行为不对的 `vault`。

## 三个非显然的决定

1. **三个状态是三条轴，不是三个桶。** 筛选用三档下拉（任意/有/无）而不是
   勾选框 —— 「本地=无」（只留在云端的图）是清理时最常用的一条，勾选框
   只能表达「必须有」，写不出来。
2. **Excalidraw 必须解压才能扫到引用。** 插件把场景 LZString 压成 base64 写进
   ` ```compressed-json `，压缩后 `fileId` 在正文里一个字都搜不到 —— 靠正则
   会得出「没人引用」，进而把在用的图当失联删掉。
   ⚠ **载荷是折行的**（实测每 256 字符折一次），解压前必须 `replace(/\s+/g,"")`，
   否则位流错位 → 返回 null → **不报错**，只是「图被判成失联」。
   校准办法：把测试库真实文件的载荷存成夹具（`tests/features/images/fixtures/`），
   并用 `jx3dps-online-public/node_modules/lz-string` 官方实现当基准 ——
   自己造的样本不带折行，这条真实细节永远发现不了。
3. **批量压缩不改容器**（保持原扩展名）。换容器要改文件名，而文件名被笔记里的
   链接指着；一次批量操作改掉几十个文件名是用户很难复核的事。
   同理**只在变小的时候才写回**（已压过的 jpeg 再压一次往往更大）。
   重命名模板里若改了扩展名 → 整条标 `extChanged` 跳过（改名不改内容，
   产出的是「扩展名与实际编码不符」的文件，能存能同步但打不开）。

## 删除的两条路（别混）

- `noteDeleted`：用户在文件管理器里删图 → 攒批 → 问一句「云端也删吗」。
- `deleteImages`（面板）：用户勾选 + 点按钮 → 云端处置**在点之前**已选定 →
  删完**绝不能再问一遍**。靠 `panelDeleted: Set` 抑制，且每批开始前 `clear()`
  （残留标记会让用户后来手动删同名文件时悄悄跳过询问，「该问不问」更糟）。
- 顺序必须是**先云端、后本地**：`trashFile` 会触发 `noteDeleted`，云端先删掉
  （记录一起清掉）后 `hasRemoteBackup` 就是 false，那次询问自然不会弹。
- 边界检查放在**列举云端之前**：越界路径一个请求都不该发。
- 墓碑在「清单里本来没有这条」时也要建（`markRemoteOnlyForced`）——
  面板是从云端列举出发的，知道云端确实有这一份（换设备/清过存储时清单是空的）。

## 踩到的两个工具坑

- **`en.ts` / `zh-cn.ts` 是 CRLF**：用 node 脚本做多行字符串替换时，
  搜索串必须先 `.replace(/\r?\n/g, "\r\n")`，否则 `includes` 恒假 ——
  而**单行替换却会成功**，症状像「脚本跑了但只改了一半」。
- **`/tmp/xxx.mjs` 在 Windows 上被解析成 `F:/tmp/xxx.mjs`**（与 python 同一个坑）：
  临时脚本要写到工作区内再用相对路径调用。

### 改了什么

- `DEFAULT_SETTINGS.images.folders`：`[]` → `["."]`（仓库根目录 = 整个库）。**没有做迁移**：
  老用户的 `data.json` 里已持久化 `[]`，不悄悄改他们的受管范围；想要新默认的用设置页
  「恢复默认」。新的「同步只复制不删除」之下，整个库作为默认范围的代价只剩「多传几个
  `.obsidian` 里的小图标」。
- 新增 `features/images/ui/FolderSuggestModal.ts`：列出 vault 全部文件夹（根目录排最前），
  支持搜索，已受管的项标注「已在受管范围」。选中回调拿归一后的路径。
- 设置页「受管的图片文件夹」下方多一行（无名称的设置行，与页面底部那排操作同形状）：
  「浏览…」打开选择器；「恢复默认」重置为默认值，**已是默认值时置灰**。
- i18n：新增 `foldersBrowse` / `foldersReset` / `folderPickerPlaceholder` /
  `folderPickerRoot` / `folderPickerIncluded`；`foldersDesc` / `foldersEmpty` 注明默认值。

### 顺手修掉的坑（都是这次默认值直接踩上的）

1. **`normalizeFolders([""])` 返回 `[]`** —— `""`（整个库的规范形状）被当成空行丢掉。
   后果：默认值落盘后读回变成「什么都没管」，且 `imageSyncService.configProblem()` 每次
   重跑 normalizeFolders 都会误报 `noFolders`。修法：`normalizeFolders` 保留 `""`，
   只丢纯空白（`"   "`）；**空行过滤移到文本解析侧** `parseFolders()`（拆行产生的 `""`
   与规范形状长得一样，两者处置必须相反）。
2. **坏形状的 `folders` 会被 `mergeWithDefaults` 换成默认值** —— 默认值现在是整个库，
   于是一个手改坏的 `folders`（字符串/数字/对象）会变成「同步全部」。修法：
   `normalizeSettings` 读**磁盘原文**判形状，坏形状退空数组，只有「缺失」才拿默认值。
3. 设置页注意事项里两条**已失效的双向删除文案**（该行为今天早些时候刚去掉）换成了
   现行的「只复制不删除 + 删本地时问一句」。
